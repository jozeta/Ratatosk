About Ratatosk

Version …

Ratatosk is a self-hosted, end-to-end encrypted way to send files and messages. Everything is encrypted in your browser before it is uploaded, and decrypted in the recipient's browser after it is downloaded. The server stores and passes along ciphertext, but it can't read your files, their names, or the keys that unlock them.

In Norse mythology, Ratatosk is the squirrel who runs up and down the world tree Yggdrasil, carrying messages between the eagle at the top and the dragon at the roots. He delivers every message without being able to read it - which is exactly the job of this server.

How it works

  1. Your browser creates a secret for the file. Either a random 256-bit key, or one derived from a passphrase you choose (PBKDF2-SHA256, 600,000 iterations).
  2. It splits that secret in two (HKDF): an encryption key that never leaves your device, and a separate download token. Knowing the token reveals nothing about the encryption key.
  3. The file - including its name and type - is encrypted with AES-256-GCM in 1 MiB segments, so large files never have to fit in memory. Each segment is authenticated, and the segments are chained, so any tampering, reordering or truncation is detected.
  4. Only ciphertext is uploaded. The server keeps a hash of the download token and requires the token before it hands out the file, so someone who only knows a file's address can't download, use up or destroy it.
  5. The key travels in the link after the #. Browsers never send that part of a link to the server. With a passphrase instead, nothing secret is in the link at all - share the passphrase separately.

What the server can and can't see

Can't see

  • File contents
  • File names and types
  • Decryption keys and passphrases
  • Text messages you send

Can see

  • The encrypted size of each file
  • When files are uploaded and downloaded
  • The declared file extension (used for upload rules)
  • Network addresses, unless the operator turns on the privacy settings

What you have to trust

Ratatosk runs in your browser, and your browser gets that code from this server. An operator who wanted to (or was forced to) could serve modified code that captures keys - the same limitation every browser-based encryption tool has. If that is part of your threat model, use an instance run by someone you trust, or the command-line client, which encrypts locally without any code from the server. Sharing with another account is end-to-end once the recipient has set up encryption keys. For recipients without keys, the site may fall back to holding that one file's key on the server - the share dialog tells you when that happens.

Ratatosk deliberately does not scan uploads for viruses: a server that can scan files can also read them. Treat files from people you don't know with the usual care.

Verify this instance

Every script on these pages is pinned by a cryptographic hash (Subresource Integrity), and all of them together are summarised by one release digest. This server reports:

Version …
Release digest …

A page can't truly vouch for itself - a server that changed the code could change this number too. To check independently, compare the digest published for this version in the release notes, or run from your own computer: 

python cli/ratatosk.py verify https://this-server --expect <published digest>

Features

  • Files of any size, streamed - uploads resume after a dropped connection
  • Several files behind one link, or encrypted text messages
  • Expiry times, download limits and burn-after-download
  • Optional passphrase as a second, out-of-band secret
  • Location and author data removed from photos before encryption
  • Request links: anyone can send you files that only you can open - no account needed
  • End-to-end sharing between accounts, with your own encryption keypair
  • Accounts with two-factor authentication, single sign-on (OIDC), API keys and a command-line client
  • Verifiable code: every script pinned by hash, and a ratatosk verify check you run yourself
  • Privacy controls for the operator: zero-log mode, IP masking, timestamp fuzzing
  • No third-party scripts, fonts or trackers - safe to run on an onion service
